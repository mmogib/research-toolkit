# 001 — Skill extraction plan, design review

## VERDICT

**Build it with changes, but do not start commit 1 from the current spec.** The main architecture is right: make the root `CLAUDE.md` a lean hub, put adoption on `/init-project`, and extract the three reusable procedures while leaving arrangements with their hosts. The remaining defects are at the execution boundaries. In particular, the proposed three-slot numerics contract is still incomplete, `/review-paper` cannot safely dispatch by renumbered item number, `/channels` conflates receipt with adoption, and the commit sequence introduces consumers before their providers. These are repairable without rethinking the extraction itself.

## BLOCKING

1. **`notes/skill-extraction-plan.md:169-185` — the `/numerics-audit` contract still omits two inputs needed by the extracted procedure.** `findings destination` cannot parameterize lens C's `notes/litrev/<Key>.md`: that path is an evidence source, not a findings sink (`skills/join-revision/references/numerics-audit.md:74-79`). The disposition table also drops the host's existing “nobody available” case (`skills/join-revision/SKILL.md:53-55`). As written, a standalone audit in a self-owned project without litrev records, or a text-only audit with no experiment runner, has no defined behavior. **Alternative:** define four explicit modes—`collaborator-owned`, `self-owned`, `no-runner`, and `referee`—and give each mode values for evidence lookup, findings sink, markup/edit policy, experiment handoff, and decision owner. Lens C uses the evidence policy; lens F uses the handoff policy. This is simpler and safer than trying to make three loosely typed slots cover both.

2. **`notes/skill-extraction-plan.md:253-280` — checklist-only mode fixes timing but not item identity.** `/review-paper` currently skips inapplicable items and renumbers the survivors (`skills/review-paper/SKILL.md:55`), while its defaults and execution guidance use fixed numbers (`skills/review-paper/SKILL.md:82-96,122-141`). After any skip, “item 12” need not be Bibliography Integrity, so the planned `/litrev` delegation can fire for the wrong item; adding another item increases the ambiguity. **Alternative:** retain stable canonical IDs or slugs and mark inapplicable items `N/A`; never renumber for dispatch. Insert Numerical Experiments Audit as canonical item 13, move Style Pass to 14, and invoke subskills by slug/title rather than display number. Define checklist-only precisely as Phases 1-3: discover context, create/confirm the checklist, add project-specific items, then return before task distribution or execution.

3. **`notes/skill-extraction-plan.md:200-208` — `/channels` records an “adopted” decision too early.** A reply landing proves only that a reply exists. The protocol separately says a Codex verdict is input to Claude's verification and never a substitute for it (`skills/join-revision/references/channels-protocol.md:63-73`). The proposed step 4 collapses receipt, verification, user decision, and adoption into one event. **Alternative:** on landing, update `Replied` in the index and link the reply from the owning topic note as pending; independently verify it; only after Mohammed accepts the conclusion record `adopted`, `rejected`, or `partially adopted` in the topic note and the index's outcome field.

4. **`notes/skill-extraction-plan.md:375-391` — the revised commits still do not each leave a working toolkit.** Commit 1 gives `/init-project` litrev-by-default and a channels opt-in before `/litrev` and `/channels` exist in commits 2 and 3 (`notes/skill-extraction-plan.md:250-256`). Commit 1 also names `guides/experiment-workflow.md`, whose planned phase 9-11 touchpoints target not-yet-created skills (`notes/skill-extraction-plan.md:302-304`). Commit 4 says `spec-note.md` is moved, but `/join-revision` still references its old path until commit 6 (`skills/join-revision/SKILL.md:117,223,259`). **Alternative:** make commit 1 hub/adopt-only; update `/init-project`'s litrev behavior in commit 2 and channels behavior in commit 3; defer the experiment guide's phase 9-11 wiring to commit 7; in commit 4 copy the spec template while retaining the legacy reference, then delete the legacy copy in commit 6 after `/join-revision` is rewired.

5. **`notes/skill-extraction-plan.md:64-78,289-305,332-373` — the hub entry-point/dependent inventory is not complete.** The missed entry point is `/suggest-journals`: it is explicitly usable for “a new paper,” reads root `CLAUDE.md` for paper context, and writes a dated underscored note (`skills/suggest-journals/SKILL.md:20-38,90-99`). It is absent from the manifest, so an old or missing hub receives no adopt prompt and its output violates the new notes doctrine. **Alternative:** add `skills/suggest-journals/SKILL.md` and `skills/suggest-journals/references/output-template.md` to the manifest; give it the same missing/old-hub preflight, read `notes/manuscript-map.md` plus the manuscript for detailed context, and update one undated `notes/journal-suggestions.md` in place. Apply the missing/old-hub preflight—not merely the manuscript-map pointer—to `/ai-slop` and `/prepare-submission` as well, since both can also be the first skill run in an existing manuscript directory.

6. **`notes/skill-extraction-plan.md:375-391` — there is no behavioral evaluation gate for any of the three new prompts.** These files are executable instructions for future sessions; two prose reviews do not show that a fresh session selects the right mode, respects host boundaries, or avoids duplicate delegation. **Alternative:** before writing each skill, record at least three baseline scenarios, then forward-test the completed skill on the same raw artifacts. Minimum matrix: numerics in all four modes; litrev for existing-manuscript, writing-from-notes, and missing-PDF cases; channels for scaffold, adversarial composition, and reply receipt/adoption. Make passing those scenarios a condition of each skill's commit.

## WORTH FIXING

1. **`notes/skill-extraction-plan.md:222-244,364` — `/litrev`'s direction is parameterized, but its locations and one contradictory consumer are not.** The source still assumes `main.tex`, a `.bib` index, a refs directory, and `notes/litrev/` (`skills/join-revision/references/litrev.md:28-40,92-102`). Separately, `math-research-writer` has a Citation Management section that emits formatted references from model knowledge (`skills/math-research-writer/SKILL.md:708-744`), outside the Literature Review section named in the manifest. **Alternative:** give `/litrev` two named modes (`audit-manuscript`, `build-from-reading`) with discovery rules for manuscript, bibliography, PDF root/index, and note root; then replace both `math-research-writer` literature sections and its Citation Management section with a required `/litrev` handoff. Candidate references may be recorded as unverified leads, never emitted as bibliography entries from memory.

2. **`notes/skill-extraction-plan.md:187-191` — optional numerics fan-out lacks write isolation and a dependency order.** Lens A and F both write the shared findings note, while D is supposed to re-check numbers B flagged (`skills/join-revision/references/numerics-audit.md:17,83-96,105-118`). Parallel axis agents can overwrite one another or run D before B has produced anything. **Alternative:** the parent creates claim inventory A first; B, C, and E write separate read-only axis reports; D runs after B and the table inventory; the parent alone consolidates and performs F. No subagent edits the manuscript or the shared findings file.

3. **`notes/skill-extraction-plan.md:127-141,407-412` — `adopt` is not re-entrant.** A second or interrupted run can overwrite `notes/done/CLAUDE_pre_hub.md` with an already-trimmed hub, destroying the only verbatim pre-migration copy; the plan also says nothing about an existing `notes/manuscript-map.md`. **Alternative:** make adopt a no-op when the root already matches the hub; never overwrite an existing backup; on collision create a numbered backup and report both; merge into an existing manuscript map only after showing a proposed diff and receiving approval.

4. **`notes/skill-extraction-plan.md:87-100` — keeping the root DFMethods block unchanged contradicts the lean-hub rule.** The current block is a detailed implementation summary (`templates/CLAUDE.md.template:94-110`), while v2 correctly says implementation detail belongs in the long `jcode/CLAUDE.md`. **Alternative:** replace the root block with one pointer under Structure or Toolkit and keep the detailed DFMethods content only in `templates/jcode-CLAUDE.md.template`.

5. **`notes/skill-extraction-plan.md:289-301,352-373` — the metadata and cross-reference sweep is too narrow.** `/init-project` gains an adopt use case, but the plan calls out deliberate frontmatter only for the three new skills; its current description says “new research projects” only (`skills/init-project/SKILL.md:2-6`). Adding a checklist item also leaves many literal “13-item” and “item 13” references outside the two tables, including `CLAUDE.md`, `README.md`, `/join-revision`, and `/ai-slop`. **Alternative:** include an explicit metadata/reference sweep in the relevant commits: add existing-project/adopt triggers to `/init-project`, narrow `/math-research-writer` away from revision ownership, and update all checklist-count/style-item references by repository-wide search.

6. **`notes/skill-extraction-plan.md:85,365` — `/ai-slop` still violates the new notes discipline in a file already scheduled for editing.** It writes `notes/ai_slop_<chunk-id>.md` and archives into a dated nested directory (`skills/ai-slop/SKILL.md:61,130-133`). **Alternative:** use undated topical files such as `notes/ai-slop-intro.md`, consolidate into `notes/ai-slop.md`, and move the settled topical note directly to `notes/done/`; a later sweep reopens and updates that topic rather than creating a dated hierarchy.

## WHAT THE TWO REVIEWS MISSED

- The current “skip and renumber” rule makes all number-based `/review-paper` delegations unstable; checklist-only mode does not repair identity.
- Lens C needs an evidence-source policy, and the existing no-experiment-runner arrangement disappeared from the numerics disposition table.
- `/channels` needs separate receipt, verification, and adoption transitions.
- Commit 1 still introduces consumers before `/litrev` and `/channels`; moving `spec-note.md` before commit 6 can break the live `/join-revision` path.
- `/suggest-journals` is the additional hub entry point; its output template and `/ai-slop` also retain the old dated-note doctrine.
- `math-research-writer` has a separate citation-management path that can still synthesize references even after its Literature Review section is rewired.
- Parallel numerics axes need separate outputs and a two-wave dependency order.
- `adopt` needs collision and interrupted-run semantics to preserve the original backup.
- The root DFMethods block is implementation detail that survives inside a design whose stated rule is that the root hub only points.
- The implementation sequence contains no fresh-session evaluations, despite prompt behavior—not file presence—being the feature under construction.

## WHAT SURVIVES

- The extraction rule itself: the extracted skill owns procedure; the host owns arrangement.
- The lean root hub as the single doctrine, with `jcode/CLAUDE.md` explicitly exempt because it is implementation reference material.
- `/init-project adopt` instead of another project-joining skill, including detect → propose → approve → backup → write and the rule against scaffolding into existing code.
- `/channels` as a skill. Composing bounded adversarial requests, maintaining the index, and closing the loop into the owning note are recurring procedural work; it is more than a copied README once the lifecycle is corrected.
- `/litrev` as the detailed cite-with-confidence procedure while the never-fabricate rule remains always-on in root instructions.
- `/numerics-audit` as an independent skill, including referee mode and sequential-by-default axis decomposition.
- Checklist-only mode as the right way for `/join-revision` to obtain `/review-paper`'s checklist without triggering downstream work.
- Deleting `/join-revision` Phase 3 after `adopt` becomes authoritative, and retaining the host's freeze, markup, collaborator, and review-order choices.
